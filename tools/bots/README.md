# ИИ-игроки «Духолова»

Боты со своей волей: каждый — «живой человек» со своим характером, который сам решает, чем заняться в игре,
может скучать, писать в чат, искать дыры в сервере через сырой `Game.act` — или бросить игру. Мозг — локальная
модель **Qwen2.5-7B-Instruct** (GGUF) в **llama.cpp `llama-server`** на CPU. Играют только в тестовом контуре
`https://test.duholov.ru/`. Код игры не меняется: бот управляет настоящим клиентом в headless Chromium.

## Файлы

| Файл | Что делает |
|---|---|
| `bot.mjs` | один ИИ-игрок: браузер (Playwright), вход, цикл «наблюдение → решение → действие → итог», память, логи, живой экран |
| `page-agent.js` | помощник внутри страницы: собирает наблюдение из DOM и данных игры, ходит джойстиком, шагает через Атлас, бросает оберег свайпом |
| `llm.mjs` | клиент к llama-server (таймаут, повтор, JSON по схеме, починка кривого JSON) и заглушка `LLM_URL=mock` |
| `prompt.md` | промпты на русском: системный (роль, действия, формат ответа), персона, сжатие памяти, отзыв при уходе |
| `viewer.mjs`, `viewer.html` | зритель в реальном времени (127.0.0.1:8090): живой экран, персона, цель, лента мыслей, желания, заметки |
| `offline.js` | режим `OFFLINE=1`: настоящий сервер игры (`server/game/core.js`) прямо в странице — проверка без сети |
| `run.sh` | короткие команды (бот, зритель, службы, проверка модели) |
| `setup-server.sh` | установка на сервер: Node 20, Chromium, сборка llama.cpp, модель из S3, службы systemd |
| `systemd/` | `duholov-llm.service`, `duholov-bot@.service`, `duholov-bots-view.service` |

Данные бота — `bots/<id>/` (на сервере `/opt/duholov-bots/bots/<id>/`):
`persona.json` (кто он), `memory.json` (выжимка, цели, впечатления, дневник), `state.json` (для зрителя),
`log.jsonl` (каждый шаг: время, наблюдение, ответ модели, действие, итог, снимок), `diary.jsonl` (note),
`wishes.jsonl` (wish — «хотел бы, но игра не даёт»), `errors.jsonl` (ошибки страницы, срабатывания защиты),
`exit.json` (почему бросил и отзыв), `shots/000123.jpg` (снимок каждого шага, JPEG 60%), `live.jpg` (живой кадр),
`storage.json` (вход в игру — без ключа контура).

## Как работает цикл

1. **Наблюдение** — компактный русский текст (≈ 1–1,5 тыс. токенов): экран и его текст, подсказка обучения,
   кнопки и поля с короткими ссылками (`b1`, `b2` …; «↓» — в прокрутке, «🔒» — закрыто), всплывашки, уровень и опыт,
   искры и монеты, сумка, команда и коллекция, коконы, задания дня, где Ловчий (город Атласа, координаты, Врата),
   что рядом (`o1` … — духи, Источники, Капища, Разломы с расстоянием и сторону света; ✓ — можно нажать),
   последние сообщения чата, итог прошлого действия и 5 прошлых шагов, память, дневник, цель.
   Кнопки берутся «как видит палец»: только то, что сверху и в самом деле нажимается.
2. **Решение** — модель отвечает JSON по схеме (`response_format: json_schema` → грамматика llama.cpp):
   `{"thought": "…", "goal": "…", "action": {"type": "…", …}}`.
3. **Действие** (не чаще одного в 3–5 с):
   `tap` (ref или текст; объекты карты — касание маркера), `type`, `walk` (направление или объект, до 400 м, джойстиком),
   `teleport` (город Атласа или «широта, долгота» — через настоящее окно Атласа и Врат), `open` (раздел меню),
   `back`, `throw` (свайп оберега; точность — «рука» персоны), `wait`, `chat` (канал, текст),
   `api` (сырой `Game.act(name, args)` — не больше `API_PER_MIN` в минуту), `note`, `wish`, `quit`.
4. **Итог** — что изменилось: уровень, опыт, искры, духи, предметы, новый экран, всплывашки — идёт в следующее наблюдение.
5. Раз в `MEM_EVERY` шагов модель сжимает историю в 5–10 строк памяти, «нравится / бесит» и настроение.
6. `quit` — бот уходит: модель пишет отзыв (`exit.json`), служба больше не поднимается (выход с кодом 0).

**Безопасность**: `GAME_URL` — только `https://test.duholov.ru/` (или localhost с `OFFLINE=1`), переходы на другие сайты
и новые окна блокируются, платёжные сервисы — тоже, кнопки с ценой в рублях и «оплатой» бот не нажимает,
`Game.pay` в странице отвечает ошибкой. Ключ контура (`DUHOLOV_TEST_KEY`) кладётся в память браузера при старте,
в логи, снимки состояния и `storage.json` не попадает; модель его не видит.

## Установка на сервер (Ubuntu 24.04)

```bash
# 1. код: с компьютера (или git clone репозитория на сервер)
scp -r tools/bots root@<ip>:/root/duholov-bots-src
# 2. ключи S3 для модели — /root/.duholov-s3 (как у бэкапов: AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, S3_ENDPOINT)
# 3. установка (≈ 15–25 мин: сборка llama.cpp и 4,7 ГБ модели)
ssh root@<ip> 'bash /root/duholov-bots-src/setup-server.sh'
# 4. ключ тестового контура — впишет владелец
ssh root@<ip> 'nano /etc/duholov-bots.env'      # DUHOLOV_TEST_KEY=…
# 5. проверить модель и запустить бота
ssh root@<ip> '/opt/duholov-bots/app/run.sh llm-test && systemctl enable --now duholov-bot@bot1'
```

Модель: `s3://duholov-models/qwen2.5-7b-instruct/qwen2.5-7b-instruct-q4_k_m-00001-of-00002.gguf` и `…-00002-of-00002.gguf`
(llama.cpp грузит разбитую модель по первому файлу) → `/opt/models/qwen2.5-7b-instruct/`.
`duholov-llm.service`: `llama-server -t $(nproc) -c 8192 --parallel 2 --jinja` на 127.0.0.1:8080.
Два параллельных слота — два бота думают одновременно; больше ботов — в очередь (по 20–60 с на ответ).

## Смотреть

```bash
ssh -L 8090:127.0.0.1:8090 root@<ip>
# и в браузере: http://localhost:8090/
```

Слева — список ботов, в центре — живой экран (кадры CDP `Page.startScreencast`, ~3 в секунду), справа — персона,
цель и мысль, счётчики (уровень, духи, виды, время в игре, шаги), лента «Мысли и действия» (последние 50, со снимками),
«Желания», «Заметки», «Память». Если бот бросил игру — сверху его отзыв и оценка.

## Команды

```bash
./run.sh start bot1 bot2      # боты-службы (systemctl enable --now duholov-bot@…)
./run.sh stop bot2
./run.sh status               # службы, модель, кто чем занят
./run.sh logs bot1            # журнал (logs llm — модель)
./run.sh bot bot3             # бот в этом терминале
./run.sh reset bot3           # забыть бота: новая персона и новый аккаунт при следующем запуске
BOT_FORCE=1 ./run.sh bot bot1 # запустить бота, который уже бросил игру
```

Переменные (`/etc/duholov-bots.env` или окружение): `GAME_URL`, `DUHOLOV_TEST_KEY`, `LLM_URL` (или `mock`),
`LLM_TIMEOUT_MS` (180000), `LLM_MAX_TOKENS` (260), `LLM_TEMP` (0.8), `BOTS_DIR`, `BOT_VIEW_PORT` (8090),
`ACT_GAP_MIN_MS`/`ACT_GAP_MAX_MS` (3000/5000), `API_PER_MIN` (4), `MEM_EVERY` (10), `CHAT_EVERY` (4),
`MAX_STEPS` (0 — без конца), `SHOTS_KEEP` (3000), `BOT_FPS` (3), `OBS_MAX_CHARS` (5200), `BOT_TZ`, `HEADLESS` (0 — окно),
`CDP_URL` (подключиться к уже запущенному Chromium), `PLAYWRIGHT_PATH`, `PW_CHANNEL` (`msedge`/`chrome` — установленный браузер вместо Chromium Playwright).
Карта в `OFFLINE=1`: `TILES_REMOTE=1` — настоящая карта мира с duholov.ru (кэш в памяти, не больше 3 запросов сразу), иначе — локальный `.pmtiles` (`OFFLINE_TILES` или `www/tiles/`; вне него карта пустая, а с 5.1.13 без карты нет и мест).

## Проверка без сети и модели (локально)

```bash
# игра: powershell tools/serve.ps1  (http://localhost:8780/)
cd tools/bots
GAME_URL=http://localhost:8780/ OFFLINE=1 LLM_URL=mock MAX_STEPS=30 node bot.mjs dev1
node viewer.mjs                 # http://127.0.0.1:8090/
```

В `OFFLINE=1` сервер игры (`server/game/core.js`) работает прямо в странице с базой в памяти (прогресс — в localStorage
страницы), места вокруг придумываются, карта — из `www/tiles/*.pmtiles`. `LLM_URL=mock` — эвристика со случайностью
вместо модели. Playwright берётся из `tools/bots/node_modules`, иначе из `tests/node_modules`; браузер — свой или
`CDP_URL=http://127.0.0.1:9333`.
